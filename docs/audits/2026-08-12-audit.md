# Code Health Audit — 2026-08-12

## Summary

- **Review window:** 2026-08-08 → 2026-08-12 (323 commits by 1 author, excluding merges and GitButler workspace commits)
- **Files reviewed:** 663 first-party files touched in the window, against the whole tracked tree — Rust, Swift, protobuf, SQL, Terraform and the web one-pager, with generated Swift excluded. Roughly 130 of them are hot.
- **Findings:** 2 critical, 45 warnings, 34 suggestions (81 after merging 3 duplicate reports across agents)

Four days, 323 commits, and an entire new backend feature, a rewritten model provider, a session-credential layer, live heart rate from the wrist, spoken voice cues, a Live Activity, a metrics listener, six migrations, and the iOS Home surface rebuilt twice. The structural discipline survived all of it: the Rust three-layer contract holds without a single exception, no service takes `Arc<AppState>`, no SQL sits outside a `repository.rs`, every one of the 21 per-person handlers calls `identity::require`, every per-person statement carries its ownership predicate, and the Swift target graph's five invariants are all still compiler-enforced. `user_technique/validation.rs` and the `PulseMonitor`/`PulseRelay` pair are the best new code in the repo.

What did not survive is everything second-order. Documentation drift is now the single largest category in this report, the accessibility work the last audit called "genuinely careful" was lost on the surfaces that got rebuilt, and the product going free took the assistant's cost model with it without anything downstream noticing.

### Top Priority Items

1. **Nothing bounds aggregate Bedrock spend** — the per-user ceiling is 50 calls/day for every tier, and the unit it counts against is a self-minted UUID that one address can create ~14,400 of a day ([SEC-001], `crates/api/src/features/assistant/types.rs:311-315`, `crates/api/src/throttle.rs:56`)
2. **One assistant request demands 13 concurrent pool connections against a pool of 10** — two or three concurrent users start hitting sqlx's 30-second acquire timeout ([PERF-001], `crates/api/src/main.rs:19,34`, `assistant/service.rs:115-141`)
3. **Eight doc statements across four files say the language model is Coach-gated** — including the deployment runbook's claim that spend is bounded by paid subscriptions, which is the operator's only view of finding 1 ([ARCH-001], `docs/deployment.md:135,137` and six more)
4. **The watch's transport controls leave the accessibility tree when they auto-hide** — for most of a session a VoiceOver user has no reachable Pause or End ([PERF-008], `ios/OndWatch/Features/Session/SessionView.swift:27,94,108`)
5. **A session credential's 90-day idle expiry is never evaluated at use time** — the sweep only runs when somebody else signs in, so an abandoned credential authenticates indefinitely ([SEC-002], `crates/api/src/identity/repository.rs:55-85`)

## Cross-Cutting Concerns

### Root cause: the product went free, and nothing downstream followed

[SEC-001], [ARCH-001], [PERF-001] and [PERF-004] are one story told from four angles. `daily_model_calls` now returns `Some(50)` for `Free`, `Plus` and `Coach` alike — "the tier decided this until the whole product went free" — and `every_tier_reaches_the_model_on_one_shared_ceiling` pins it. That single change invalidated three separate things, and each was left standing:

- **The cost control.** The quota is still per-identity, and `throttle.rs`'s own module doc identifies the hazard ("every row it leaves behind carries its own assistant allowance and therefore its own Bedrock spend") before stopping at bounding row creation. When the tier gated the model, a paid subscription was the scarce thing; now the scarce thing is a UUID, which is free. Nothing anywhere — not the breaker, which trips on consecutive failures rather than cost, not `infra/main.tf`, which provisions no AWS Budget — caps the aggregate.
- **The operator's view of it.** `deployment.md:135` still tells whoever is on call that "nobody could [spend money], because a chat request needs the Coach tier". That is the runbook sentence that would otherwise prompt someone to go looking.
- **The load model.** With every identity reaching the model, `read_context`'s 13-connection fan-out stopped being a paid-tier-rate problem and became a first-launch-rate one.

Fix the ceiling first ([SEC-001]) — it is the one with a bill attached. [ARCH-001] should land in the same change, because a runbook that contradicts the fix is how the fix gets reverted.

### Systemic: documentation drift is the repo's dominant failure mode, and it is accelerating

Sixteen of the 81 findings are documentation that has outlived its subject: [ARCH-001], [ARCH-004] through [ARCH-008], [ARCH-012], [ARCH-014], [ARCH-015], [ARCH-019], [OBS-001], [OBS-008], [OBS-010], [QUAL-012], [QUAL-017] and the merged category-table finding. That is a fifth of the report, and the previous audit flagged the same pattern under the same heading.

The shape is now clear enough to name. Two constructions produce nearly all of it:

- **Counted nouns.** "the one streaming RPC", "its two queries", "with four [fields]", "The one tool the chat declares", "two app targets", "two append-only tables", "Shared by both instructions". Every one of these expired, several within days of being written. A count nothing enforces is a claim with a timer on it.
- **"Not yet" claims.** `architecture.md:81`'s "no token and no signature" survived the arrival of `identity/credential.rs`, `jws.rs`, a `ond-session-credential` header and an e2e test pinning it, and now directly contradicts `transport.md:62`.

Two of these have expired **twice** across consecutive audits: the Swift log-category table ([OBS-001], now missing nine of 29) and the `docs/architecture.md` component table ([ARCH-008], which gained rows for `account` and `user_technique` and immediately lost them for `crates/toolkit` and `ios/OndActivity`). A third pass of manual correction is not the answer. [OBS-001]'s action is the right one and should be generalised: the category table can be checked mechanically by grepping `category:` across `ios/`, exactly as `check:diagrams` keeps the site's figures honest. `check:doc-links` already proves the model works; it simply does not cover backticked code paths, which is why [ARCH-006] — two docs sending contributors to a `seed.rs` that no longer holds the catalogue — slipped through a gate that passes 41/41.

### Pattern: the new code is excellent and its second-order work is missing

Every agent independently reported that the newest surfaces are the strongest code in the repo. `user_technique/validation.rs` is 276 lines of logic to 410 of tests, documents its cross-stage blackout rule with the physiology behind it, and refuses a phase kind with no seeded range rather than inventing one. `assistant/tools.rs` puts `deny_unknown_fields` on all three tools, resolves every slug against the seeded catalogue, and re-runs a proposed exercise through `user_technique`'s own validator before emitting a card. The Bedrock rewrite discards its probed credentials, never logs a prompt or completion body, and deliberately never reads the provider's `message` field because moderation refusals quote the input back. `PulseMonitor`/`PulseRelay` has three independent end conditions and change-guarded observable writes.

What consistently did not arrive with it: the doc comments ([QUAL-016]), the log categories ([OBS-001]), the client-side decode tests ([QUAL-005]), and the VoiceOver labels. This is a better failure mode than the alternative, but it is the same one the previous audit named, and it means each wave leaves a uniform trail of small omissions rather than a few large ones.

### Cross-language drift: the zero value is refused on one side and accepted on the other

Four findings sit on the same seam. [TYPE-001], [TYPE-002] and [TYPE-003] are all Swift decoders folding a wire value the app cannot represent into a real domain case — `.unspecified → .nose`, `.UNRECOGNIZED → .plain`, `?? .fullScreen`. In each, the surrounding code documents exactly why that is wrong, and the lenient arm sits beside the argument against it. [TYPE-001] is the previous audit's [TYPE-001] half-fixed: `.UNRECOGNIZED` now throws and `.unspecified` still guesses, on the same round-trip path where `TechniqueDraft(copying:)` writes the guess back over somebody's authored exercise.

[TYPE-004] is the mirror image and the more interesting one: a `_ =>` catch-all on a database enum, in Rust _and_ in its deliberate Swift twin, deriving `hold_after` — which feeds `PhaseLimits::range`, the safe-duration lookup. The two-site duplication is documented and intentional; what it was supposed to buy is that a fifth `phase_kind` breaks both builds. The catch-all spends exactly that.

The rule for all four: a value the app cannot represent is a decode failure, never a default. Fixing three of them one-sidedly would leave the seam in the state that produced them.

### Emerging: cross-feature reach-through

Four findings say a feature boundary is being crossed rather than used. [ARCH-002] is the only `use crate::features::…::repository::…` in the crate — `state.rs` reaching into `user_technique` for `PhaseLimitsCache`, which the assistant's handler then reads. [ARCH-003] has `obs/metrics.rs` importing `features::entitlement`, the one place infrastructure depends on a feature rather than the reverse. [QUAL-003] has four features importing six `pub(crate)` conversion functions out of `technique/service.rs`, making a service module into an implicit shared-utility surface. [QUAL-006] has the chat's tool dispatch living in the transport adapter, so adding a fourth tool means editing two files.

None is serious alone; together they are the beginning of the junk-drawer shape the conventions ban, arriving one tier down as a file rather than a directory. All four have the same fix — publish the thing deliberately, in a named sibling, from the feature that owns it — and [QUAL-003] should go first because `features/user_technique/convert.rs` already exists as the pattern to copy.

### Contradictions resolved

**`bedrock.rs`: split the file, or extract the relay in place?** [ARCH-009] proposes promoting to a directory (`client.rs` / `wire.rs` / `events.rs`); [QUAL-004] proposes extracting the 117-line spawned relay as a free function so it can be unit-tested. These are sequential, not competing. Do [ARCH-009] first; [QUAL-004]'s `relay` then lands in `model/bedrock/client.rs` with its tests beside it. Attempting [QUAL-004] alone leaves an 974-line file with one more function in it.

**`harness.rs`: two proposed splits.** [ARCH-011] proposes five files, [QUAL-013] four, collapsing `app.rs` into `database.rs`. Adopt [ARCH-011]'s five — the router-assembly helpers change for different reasons than the database lifecycle, and `mod.rs` re-exporting means no suite's `use harness::…` changes either way.

**Escalating shared Swift components.** [QUAL-008] (`RetryNotice`) and [QUAL-010] (`RatherNotSayOption`) both promote code to the app-local tier. Three-tier escalation permits this — each has three concrete consumers today, not a speculative second one — so both stand. [QUAL-008] correctly leaves the watch's copy duplicated, which is the documented rule.

**A "missing test" that is not one.** No agent filed against the four categories `docs/testing.md` excludes, and none needed dropping. [QUAL-005]'s finding is the opposite shape — a guard whose whole purpose is preventing a `ClosedRange` trap, on the contract's newest safety-relevant message, with nothing testing it on the client side.

### [PERF-001] One assistant request demands 13 concurrent pool connections against a pool of 10

- **Severity:** Critical
- **Location:** `crates/api/src/main.rs:19,34`; `crates/api/src/features/assistant/service.rs:115-141`
- **Issue:** `read_context` is a `tokio::try_join!` of five branches, two of which fan out again: `technique::catalogue` is itself a `try_join!` of 3 (`technique/service.rs:105-110`) and `journey::practice_snapshot` a `try_join!` of 7 (`journey/sessions/service.rs:315-327`). Peak simultaneous acquisitions for a single chat/explain/recommend RPC is 3+1+1+7+1 = **13**. `MAX_DB_CONNECTIONS = 10`, with no `acquire_timeout` override (sqlx default 30s). `GetJourney` adds 4 more.
- **Impact:** No deadlock — no future holds a connection while acquiring another — but one assistant request exhausts the pool and self-queues. Two or three concurrent assistant users plus a journey read will start hitting the 30s acquire timeout, which surfaces as request failures rather than slowness. This fails at trivial load, before any real traffic, and [ARCH-001]'s change (every tier reaches the model) is what moved the assistant from a paid-tier-rate path to a first-launch-rate one.
- **Action:** Fix the fan-out, not the pool size — raising `max_connections` alone hides the shape. Do [PERF-004] first: caching `technique::catalogue` + `technique::reference` removes 6 of the 13. Then set an explicit `acquire_timeout` (2–5s) so exhaustion fails fast and visibly instead of hanging for half a minute.

### [SEC-001] Nothing bounds aggregate Bedrock spend — the ceiling is per-identity, and identities are free to mint

- **Severity:** Critical _(upgraded from the agent's Warning — the per-user control is correct and the aggregate exposure is uncapped, unmonitored, and attached to a real bill on a deployed box)_
- **Location:** `crates/api/src/features/assistant/types.rs:311-315`; `crates/api/src/throttle.rs:56,69`; `infra/main.tf`
- **Issue:** `daily_model_calls` returns `Some(50)` for every tier including `Free`. The quota is correctly claimed server-side, per user, before the provider call — but the unit it counts against is a self-minted UUID, and `NEW_IDENTITIES_PER_WINDOW = 10` per IP per minute permits ~14,400 fresh identities a day from one address, each arriving with its own untouched allowance of 50 calls at `CHAT_MAX_TOKENS = 850` plus a large cacheable prefix. `REQUESTS_PER_WINDOW = 600/min` is not a binding constraint on that. Nothing anywhere caps aggregate spend: the breaker trips on consecutive _failures_, not on cost, and `infra/main.tf` provisions no AWS Budget. `throttle.rs`'s own module doc names the hazard ("every row it leaves behind carries its own assistant allowance and therefore its own Bedrock spend") and stops at bounding row creation.
- **Impact:** A single address can drive on the order of 10⁵–10⁶ Bedrock invocations a day against the instance profile. The per-user control works exactly as designed and still leaves the bill unbounded, because the design assumes the identity is scarce — which it was while the model was Coach-gated, and is not now. Pre-launch obscurity is currently the only thing limiting this, which is precisely the wrong thing to rely on: the box is deployed, the API is public behind Caddy, and TestFlight builds ship against it. [ARCH-001] means the runbook tells whoever is on call the opposite.
- **Action:** Add a process-wide daily call ceiling checked in `claim_call` alongside the per-user one (a counter on `assistant_usage` summed by date, or an in-process budget on `AppState`), degrading to the rule-based fallback exactly as the existing quota exhaustion does — `an_exhausted_quota_answers_from_the_rules` already pins that behaviour. Back it with an AWS Budget action on the Bedrock spend in `infra/main.tf` so the ceiling has a second, out-of-band enforcer. Land [ARCH-001] in the same change.
- **Cross-referenced by:** ARCH, PERF

#### Warnings — Security & Hygiene

### [SEC-002] A session credential's 90-day idle expiry is never evaluated at use time

- **Severity:** Warning
- **Location:** `crates/api/src/identity/repository.rs:55-85` (the `credentialed` `EXISTS`), `:144-153`; `crates/migrate/migrations/0020_user_sessions_expiry.sql`
- **Issue:** `standing()`'s `EXISTS (SELECT 1 FROM user_sessions WHERE user_id = … AND token_hash = $2)` carries no `last_seen_at` predicate. The expiry that 0020 promises is enforced solely by the sweep riding `start_session` — "on the next sign-in from anybody." On a deployment where nobody signs in for a stretch, a credential idle for years still authenticates; the row is only deleted once some unrelated person signs in.
- **Impact:** The stated lifetime in `web/privacy.html` and 0020 is not the lifetime the request path enforces. A credential lifted from a decommissioned device, a restored backup, or a stolen-then-abandoned handset stays live indefinitely rather than for 90 days. This is the "cached with no expiry evaluation" shape, on the repo's only bearer credential.
- **Action:** Add `AND user_sessions.last_seen_at >= now() - interval '90 days'` to the `EXISTS` in `standing()`. It costs nothing on a primary-key lookup, makes the sweep purely a storage concern rather than the security control, and the existing once-a-day `last_seen_at` refresh already keeps the value accurate to within a day of a 90-day bound.

### [SEC-003] Sign in with Apple accepts no nonce, and what a replayed token buys has grown

- **Severity:** Warning
- **Location:** `crates/api/src/features/account/verifier/apple.rs:26-40`; `crates/api/src/features/account/repository.rs:148-176`
- **Issue:** The `nonce` claim is deliberately not read. The module's own doc states the consequence precisely: a replayed identity token "returns the token owner's `user_id` and a live credential for it (or, racing a first-ever sign-in, binds the victim's Apple account to a row the attacker already holds a credential for)." The doc's stated trigger for revisiting is "the credential a sign-in mints starting to buy something the account itself does not" — and in this window it began minting a credential valid for 90 days of idle (in practice longer, per [SEC-002]), where before the token proved identity only for the ten minutes of its own life. **The doc's own revisit condition has fired.**
- **Impact:** One captured identity token converts into persistent account takeover: read and rewrite the profile, spend the assistant allowance, and `DeleteAccount`. `bind_apple_account`'s merge path also folds the attacker's identity into the victim's row and deletes the attacker's, so the attacker's own history lands on the victim's account. Practical exploitability remains low — the token is minted by Apple for this app's audience and travels to the server over TLS — which is why this is a Warning rather than a Critical.
- **Action:** Issue a server challenge, return it from a new RPC (or piggyback the existing sign-in preflight), have the client pass it to `ASAuthorizationAppleIDRequest.nonce` as its SHA-256, and compare it in `Claims::into_verified` alongside `iss`/`aud`/`exp`. Single-use, short-lived, stored in the same `user_sessions`-shaped way. Keep the existing acceptance note but reframe it as the reason the nonce now exists.

### [SEC-004] `.env` redaction was removed on a rationale that no longer holds — it carries a live API key

- **Severity:** Warning
- **Location:** `.mise.toml` `[env]` (`_.file = { path = ".env" }`), commit `b77f9263`
- **Issue:** The commit removed `redact = true`, reasoning that "the file holds Apple identifiers — a team id, an API key id, that key's issuer id — while the one real credential is the `.p8`, a file outside the repository." The `.env` on this machine holds `OND_DEV_TEAM` **and `ELEVENLABS_API_KEY`** — a live third-party billing credential, read by `crates/toolkit/src/voice.rs:460` and documented in `docs/voice.md:62` but absent from the `.env` table in `docs/contributing.md:107` that the commit's reasoning was drawn from. It is now exported unredacted into the environment of every `mise run` task and printed in full by `mise env`. This is the previous audit's SEC-004 recurring with a new subject: that key was OpenRouter's, it was removed, and a different live key took its place in the same file.
- **Impact:** Any task output, `mise env` paste, screen share, or CI log capture from a machine that renders voice leaks a billable ElevenLabs key. The two-variable backend rule itself is intact — no server-side variable is in `.env`, and `env::var` usage across the workspace is exactly `OND_ENV`, `DATABASE_URL`, build-script vars, and this one toolkit key. `.env` is correctly untracked.
- **Action:** Do not restore `redact = true` — the stdin-capture reasoning is sound and load-bearing for `db:psql` and `tofu apply`. Instead move `ELEVENLABS_API_KEY` out of `.env` into the developer's own shell or a keychain lookup that `generate:voice` shells for, so `.env` again holds only the Apple identifiers the commit's rationale describes. Add a line to `docs/contributing.md`'s `.env` table stating that rule, since its omission is what let the drift happen silently twice.

#### Suggestions — Security & Hygiene

### [SEC-005] The Bedrock streaming path has no absolute ceiling, only an inter-frame one

- **Severity:** Suggestion
- **Location:** `crates/api/src/features/assistant/model/bedrock.rs:234-256` vs `:171-199`
- **Issue:** `complete()` overrides `operation_timeout(REQUEST_TIMEOUT)`; `stream()` deliberately does not, and relies on `StalledStreamProtectionConfig` with a 30-second grace. That bounds silence between frames but places no ceiling on total duration — a provider dribbling one frame every 29 seconds holds the spawned task, the channel, and the tonic stream indefinitely.
- **Impact:** Low in practice: the `sender.closed()` select arm releases everything the moment the client hangs up, and the per-user quota bounds concurrent streams. It is the one provider path with no absolute bound, which matters more now that [SEC-001] makes concurrent streams cheap to obtain.
- **Action:** Wrap the spawned decode loop in a `tokio::time::timeout` of a few minutes — long enough that no compliant `CHAT_MAX_TOKENS = 850` reply could reach it — sending the existing `ModelError::Failed` down the channel on expiry so the stream ends `UNAVAILABLE` exactly as a mid-stream break already does. Fits naturally into [QUAL-004]'s `relay` extraction.

### [SEC-006] The advisory watch now exists, but only fires at deploy and is bypassable

- **Severity:** Suggestion _(downgraded from the previous audit's Warning — the mechanism landed)_
- **Location:** `.mise.toml` `[tasks."check:audit"]` and the `deploy` task's `DEPLOY_ADVISORY_ACK` escape hatch; `.github/workflows/audit.yml`
- **Issue:** The previous audit's standing finding "nobody is watching the advisory feed" is no longer true. `check:audit` runs `cargo audit` against `Cargo.lock` and `osv-scanner` against `ios/Packages/OndCore/Package.resolved`, wired into `deploy` before the image build; `audit.yml` would schedule it nightly. Dependabot was added (`187eb797`) and removed (`4604980d`, "version bumps are ours to make") — that removal took version-update PRs, not the advisory watch. What remains is that `audit.yml` cannot fire (Actions are disabled repo-wide), so the _only_ live trigger is a deploy, and it can be waved with `DEPLOY_ADVISORY_ACK`.
- **Impact:** A RustSec advisory against `ring` or `x509-parser` — which between them are the whole of both the App Store and the Sign in with Apple signature checks — is discovered whenever the next deploy happens, not overnight. In a quiet week that is a week.
- **Action:** Give the advisory scan a trigger that does not depend on shipping: a `mise run check:audit` in a local `cron`/`launchd` entry, or enabling Actions for the `audit` workflow alone. Leave the `DEPLOY_ADVISORY_ACK` hatch — its reasoning (an unrelated advisory must not block an outage fix) is right, and it is opt-in per invocation with the reason recorded.

### [SEC-007] The tools that decide whether a dependency is safe are themselves unpinned

- **Severity:** Suggestion
- **Location:** `.mise.toml:46-53`
- **Issue:** `cargo:cargo-audit`, `osv-scanner`, `cargo:cargo-machete`, `cargo:cargo-nextest`, `buf`, `protoc` and `pnpm` are all `"latest"`. `rust`, `vp`, `markdownlint-cli2` and `sqlx-cli` are pinned, each with a comment giving the reason. `cargo-audit` in particular is compiled from crates.io at whatever version resolves, then run inside `deploy` on the developer's machine with `AWS_PROFILE=ond` in the environment.
- **Impact:** A compromised release of any of these executes in the deploy path with production AWS credentials available. The pinned entries prove the project already reasons about this for reproducibility; the security-relevant tools are the ones left floating.
- **Action:** Pin `cargo:cargo-audit` and `osv-scanner` to explicit versions with a note that they are bumped deliberately, on the same footing as the `sqlx-cli` pin. The rest are lower stakes and can stay `latest`.

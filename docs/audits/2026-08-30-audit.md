## Cross-Cutting Concerns

### There is no CI, and nine documents said otherwise

GitHub Actions is off and will stay off: a one-person project does not justify the spend. `.github/` has been deleted rather than left as a workflow that drifts from the gate it no longer mirrors — which is what it had already done, omitting nine database-free tasks and `test:swift` that this window added.

The cost of the old framing was that the tree read as if something else was checking. `docs/code-structure.md:121` said `check:diagrams` "runs on CI's macOS job", which is the argument for trusting that the marketing site's figures match `OndKit/TechniqueFigure.swift` — and `ios/` and `web/` were both heavily reworked here. `docs/follow-ups.md` held an open item whose closing condition was CI returning. Both are now corrected, along with `CLAUDE.md`, `docs/contributing.md`, `docs/deployment.md`, `.mise.toml` and three skill files.

One real gap survives the decision and is now recorded as accepted rather than open: `check:audit` fails closed inside `deploy::advisory_gate`, but a deploy is its only trigger. The App Store chain check and the Sign in with Apple verifier are hand-rolled over `ring` and `x509-parser`, so between deploys nothing looks at the advisory feed for either. A calendar trigger is the half a deploy hook cannot replace, and there is nothing to carry one.

### One refactor wave, two conventions

`2b3506bb` split five monolithic e2e suites into directories and `399f8347` absorbed the mise shell into `crates/toolkit`. Both landed half-applied.

Two of the five suites came out with a declaration-only `mod.rs` and a `fixtures.rs`; three came out with 177–291 lines of fixture in the `mod.rs` and the `mod` declarations at the bottom [ARCH-004]. The paragraph in `docs/code-structure.md:162` describing the old layout still names `harness.rs`, a file that is now a six-module directory [ARCH-005]. Inside the suites, the harness publishes two RPC path constants with a doc explaining that one definition is the point, and eleven others are re-declared across four suites anyway [QUAL-005]. Eight comments in live source point at the files the split deleted, two of them cross-language pointers whose whole job is to name the twin that must agree [QUAL-006].

Three new modules use a sibling `X.rs` entry where the other twenty-five use `mod.rs` [ARCH-008]. `toolkit/comments/mod.rs` — the module that enforces the comment convention — is 605 lines and twelve times the stated limit for a module entry [ARCH-010]. `assistant/prompt/mod.rs` is twelve lines of declarations and 820 lines of tests for its siblings, with six private helpers widened to `pub(super)` purely so the test block can see them [ARCH-001].

None of these is expensive alone. Together they mean the next contributor picks a convention at random, which is how a convention becomes "the tree does both".

### Two hot spots drew three agents each

`crates/api/src/features/assistant/prompt/` — the hottest backend directory in the window — carries ARCH-001 (tests in the module entry), QUAL-008 (`instructions.rs` is the only 330-line file in the workspace with no `//!`) and PERF-008 (the cacheable prefix is rebuilt from process-constant data on every call). ### Cross-language drift on the phase contract

Migrations `0035_phase_manner` and `0039_phase_cadence` each added a field to `pb::Phase` in this window, and each had to be landed in two places: `technique/service.rs:285-315` and `user_technique/convert.rs:127-160` both construct the same nine-field message with the same three `wire::positive` labels [QUAL-001]. They have already diverged on `turn_gap_ms`. A third field added to one and not the other compiles and sends a zero value.

The same boundary has a one-sided gap on the passage. Three decoders refuse an unset passage on a moving breath — `technique/convert.rs:130-138`, `user_technique/validation.rs:210-217` and Swift's `Passage(breathing:)` — each with a comment explaining that a guessed passage is written back over the author's own when the card is re-edited. That mapping is correct — the Rust encoder writes `ReadingListStyle::None` _as_ `Unspecified` — but nothing beside it says so, so it reads as the one violation of the rule.

### The server emits what nothing reads

`mise run check:metrics` proves every name the dashboard, the rules and the docs use is one something emits. It is one-directional by design, so the opposite class can only grow, and it has: `ond_identities_created_total` and `ond_sign_ins_total` were both pre-registered at zero with comments explaining that a panel needs the series to exist, and neither appears in any panel [OBS-004]. `ond_backup_last_attempt_timestamp_seconds` is emitted, undocumented and unread — the only metric separating "the dump ran and failed" from "cron never fired" [OBS-008]. `ond_entitlement_rejections_total` was added because the alert on the count was undiagnosable without it, and the alert still tells the responder to restart production with `RUST_LOG=api=debug` [OBS-002].

The security half of the same pattern: every refusal on the identity path logs at `debug`, which production drops, and `GrpcUnexpectedFailures` excludes statuses 8 and 16 — so a credential-guessing run against `ond-session-credential` produces no alert and no log line [SEC-001]. The series already exist; only a rule is missing.

### Type Safety & Robustness

#### Type-safety critical

### [TYPE-002] A corrupt `sessions.json` reads as no history, and the next session overwrites it

- **Severity:** Critical (raised from Warning — this is silent loss of a person's own records, with no path for any caller to detect it)
- **Location:** `ios/Packages/OndCore/Sources/OndKit/JSONFileStore.swift:24-57`, callers at `ios/Packages/OndCore/Sources/OndKit/FileSessionStore.swift:27-61`
- **Issue:** `JSONFileStore.read()` returns `[Element]`, so a decode failure and an empty file are the same value. The catch block returns `[]` and says the file is left alone "to keep whatever it holds available to a later version that can read it". `FileSessionStore.record` is `file.save(file.load() + [session])` — verified — so the next completed session writes a one-element array over the file, destroying exactly what the comment promises to preserve. The same shape reaches two more paths: `remove` guards on `remaining.count != held.count`, so on a failed load it returns early and never tombstones the deletion; and `merge` treats an undecodable `deleted-sessions.json` as no tombstones, handing back sessions the person deleted.
- **Impact:** Unreadable history silently becomes lost history. Sessions already synced return from the server, so the permanent loss is bounded to unsynced records and deletions not yet drained — but nothing above this layer can tell the two cases apart, no caller is given the chance to, and the deletion path fails in the direction that resurrects data somebody asked to remove. A shape change to `SessionRecord` is enough to trigger it; `StoredIdentifierShapeTests` exists precisely because that is a live risk.
- **Action:** Make the failure representable: `read() throws -> [Element]`, or an enum (`.absent`, `.decoded([Element])`, `.unreadable(Error)`). Have `FileSessionStore.record` refuse to write over an unreadable file — hold the record in memory or append to a sidecar — and have `remove` refuse to skip tombstoning when the load failed. At minimum, rename the file aside before the first overwrite so the comment's promise is true. Log the unreadable case at `notice` so it reaches the on-disk store.

### Performance & Accessibility

#### Performance warnings

### [PERF-001] The whole cue stack is built synchronously on the main actor at the moment a session starts

- **Severity:** Warning
- **Location:** `ios/Ond/Features/Session/SessionAudioPlayer.swift:17-67,91-127`, called from `SessionCues.swift:27-30` and `OndKit/SessionModel.swift:141`
- **Issue:** `SessionModel.start()` calls `cues.prepare()` synchronously on `@MainActor`. That one call does all of: first-touch initialisation of five lazy `static let` tone buffers, which together synthesise roughly 18 seconds of 44.1 kHz audio — about 800,000 `sin` + `exp` iterations in `ToneSynthesizer.wav`; construction of five `AVAudioPlayer`s from that data; and, when a voice is chosen, fourteen more `AVAudioPlayer(contentsOf:)` from the bundle, each followed by `prepareToPlay()`. The file comment says the tones are built once "rather than per session … [they] would otherwise land on the main thread as the player animates in" — but a Swift `static let` is lazy, so the first session in every process still pays the whole cost on the main actor.
- **Impact:** A stall on the exact frame the countdown ends and the breath guide begins animating. It lands on the first session after every launch, which is most sessions in practice, and it is worst for people who chose a voice (nineteen player allocations instead of five).
- **Action:** Two independent steps. Build the tone `Data` in a `nonisolated` async function and await it, or warm the statics from a detached task when `SessionCues` is constructed rather than when `prepare()` runs. And build the fourteen voice clips concurrently off the main actor, handing the finished dictionary back — `AVAudioPlayer` creation from a URL does not require the main actor. Alternatively call `prepare()` when the countdown _begins_, so the cost is absorbed by the count-in that already exists.

### [PERF-004] The Progress log folds the whole install history on every body pass

- **Severity:** Warning
- **Location:** `ios/Packages/OndCore/Sources/OndKit/SessionDay.swift:53-99`, called from `ios/Ond/Features/Progress/PracticeProgressView.swift:101-105`
- **Issue:** `wholeDays(of:coveringAtLeast:)` reads as if it stops early — it appends days until `counted >= rows`, then breaks. But `grouped(records:)` is eager: it walks **every** record calling `calendar.startOfDay(for:)` and builds the complete dictionary before `wholeDays` looks at the first element, so the `break` saves nothing. `PracticeProgressView.content` calls it from inside `body`, alongside `PracticeRhythm(sessions: model.history, …)`, which walks the same list again.

### [SEC-004] Sandbox App Store transactions are honoured in production

The `bundleId` and `productId` checks bound the exposure to people who can obtain a sandbox transaction for this app. What is missing is any expiry: no dated `TODO`, no alert, no test pinning when it ends.
- **Impact:** Free `Plus` for anyone on TestFlight, which also means a free daily Bedrock allowance per identity. The behaviour is correct today; the risk is a temporary exception outliving its reason with nothing to notice.
- **Action:** Keep honouring sandbox transactions. Add a `TODO` naming the launch date beside the `StoreEnvironment` comment, and an alert on the sandbox share of `ond_entitlement_purchases_total{environment=...}` so the volume is visible. Revisit the gate at launch, not before.

### [SEC-006] The database password file is world-readable between creation and `chmod`

- **Severity:** Suggestion
- **Location:** `infra/cloud-init.yaml:94-105`
- **Issue:** `printf 'POSTGRES_PASSWORD=%s\n' "$(openssl rand -hex 24)" > /srv/data/ond.env` creates the file under root's default umask (0644), and `chmod 600` runs two lines later. On a first boot the window is milliseconds and only root is running.
- **Impact:** Small, and free to close.
- **Action:** Set the mode before any content lands — `install -m 600 -o ubuntu -g ubuntu /dev/null /srv/data/ond.env` and then write into it, or wrap the block in `(umask 077; printf … > /srv/data/ond.env)`.

### [SEC-007] The logs bucket omits the hardening the backups bucket writes out

- **Severity:** Suggestion
- **Location:** `infra/main.tf:152-182` compared with `:72-135`
- **Issue:** The `backups` module explicitly sets `block_public_acls`, `block_public_policy`, `ignore_public_acls`, `restrict_public_buckets` and `attach_deny_insecure_transport_policy`, with a comment arguing that stating them is what stops an upstream default changing under a major version bump. The `logs` module states none of them and explains only why versioning is omitted. `attach_deny_insecure_transport_policy` defaults to `false`, so that bucket accepts plaintext transport today.
- **Impact:** The logs bucket holds thirty-five days of application logs — support references, request paths, framework error text. Lower stakes than the dumps, but the backups comment's argument applies unchanged, and the asymmetry reads as an oversight rather than a decision.
- **Action:** Copy the four `block_public_*`/`restrict_public_buckets` settings and `attach_deny_insecure_transport_policy = true` onto the `logs` module, and extend its comment to say versioning is the only thing deliberately left off.

### [SEC-008] `/about` reports the build to anyone, unthrottled

- **Severity:** Suggestion
- **Location:** `crates/api/src/http/about.rs:49-56`, `crates/api/src/lib.rs:113-118`
- **Issue:** Caddy proxies every path on the API host, so `/about` is public. It returns the exact source commit, the build timestamp, the environment name and the assistant's live/fallback state. `throttle::enforce` is layered onto `grpc_router` alone, so neither `/health` nor `/about` is rationed — correct and documented for `/health`, incidental for `/about`.
- **Impact:** The commit hash tells an unauthenticated caller precisely which build is running, which turns "is this deployment affected" into a lookup. `assistant` additionally announces when the coach is degraded. Low on its own; free reconnaissance.
- **Action:** Decide whether `/about` is an operator endpoint or a public one. If operator, move it to the metrics listener beside `/metrics`, which is already private by construction. If it stays public, reduce the body to `built_at` and `environment` and keep the commit for the private listener.

### [SEC-009] `dev:web` resolves an unpinned npm package at run time

- **Severity:** Suggestion
- **Location:** `.mise.toml:548`
- **Issue:** `pnpm dlx serve --listen 18102 …` downloads and executes whatever `serve` currently resolves to, with no version pin and no lockfile — the only place in the repo that does. Every other tool is a `[tools]` entry, several with comments explaining why the pin matters.
- **Impact:** A compromised release of `serve` or a transitive dependency executes on a developer machine holding AWS credentials and the deploy path. Small blast radius, but the one hole in an otherwise fully pinned toolchain.
- **Action:** Add `"npm:serve" = "<version>"` to `[tools]` beside `npm:markdownlint-cli2` and call the binary directly, which also brings it under the mise-first rule the file exists to enforce.

### [SEC-010] Nothing enforces that the Tailscale auth key is single-use

- **Severity:** Suggestion
- **Location:** `infra/variables.tf:18-22`, `infra/main.tf:475-481`
- **Issue:** `tailscale_auth_key` is templated into `user_data`, which any container on the box can read back through IMDS (`http_put_response_hop_limit = 2` makes the metadata endpoint reachable from inside Docker's bridge). The variable's description states this accurately and says to mint the key single-use and tagged. That description is the whole mitigation.
- **Impact:** If a reusable key is ever supplied, a compromise of any container yields a credential that enrols new nodes onto the tailnet — the network that admits SSH and the monitoring stack (SEC-003).
- **Action:** Add a `validation` block asserting the key is ephemeral where the format allows, or move the join off `user_data` entirely: cloud-init already tolerates a failed join and falls back to SSM, so the key could be fetched from SSM Parameter Store as a SecureString at first boot and deleted afterwards, leaving nothing in `user_data`.
